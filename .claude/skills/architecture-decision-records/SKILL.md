# Architecture Decision Records

Use this skill to capture important technical decisions without turning every small task into process.

## What to Apply

- Record only decisions with lasting architectural, operational, or compatibility impact.
- Capture context, decision, alternatives considered, consequences, and status.
- Keep the ADR concise enough that future maintainers will read it.
- If `docs/adr/` doesn't exist yet, propose creating it and ask before writing the first file.
- Link related standards, issues, PRs, or follow-up tasks when available.

## Output Expectation

Produce a short ADR draft or a decision summary with alternatives and consequences.
